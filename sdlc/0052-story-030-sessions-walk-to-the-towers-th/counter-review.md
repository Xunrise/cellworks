# Counter-review

**Standards reviewed: factory:standards-change, factory:standards-security, factory:standards-testing.**

- Important: crates/agent-sessions/src/lib.rs:362 — `tower_of`'s fallback collapses two distinct cases design.md's requirement 5 separates: "without a line, the file's first function; else the file's node." Here, `landing.or_else(|| items.iter().find(|item| item.kind == Function))` is also taken whenever `event.line` is `Some` but matches no item's floors (e.g. a Read/Edit landing on a blank line, a comment, or any line not covered by an item) — it silently places the session on the file's first function instead of falling through to the bare-node placement the design requires for that case. This mis-locates the session visually (wrong tower, wrong height, wrong "writing" floor growth target) whenever an event's line isn't covered by any item, which is a routine occurrence, not an edge case. factory:standards-change rule 1 (the change matches its plan — `design.md` is the frozen, binding artifact and may not be silently reinterpreted). Fix: when `event.line` is `Some` but no item matches, skip the first-function fallback and fall through to the node-only `Placement` (as is already done when `map.items_of` returns `None` at all).
- Nit: crates/agent-sessions/src/ui.rs:203 — the "listing error" sidebar path (`SessionEvent::ListingFailed` → "Could not list sessions: …") named by design.md requirement 10 has no unit or acceptance test exercising it. factory:standards-testing rule 6: new behaviour (including the error paths the plan names) arrives with its tests. Add a test that seeds a `ListingFailed` and asserts the sidebar shows the message.
- Nit: src/app.rs:908 — the sidebar is gated on `app.sessions.has_sources() && mapped(&app.opened).is_some()`, i.e. it stays hidden until the project finishes mapping, whereas design.md requirement 10 says the panel shows "only while a project is open and the app has session sources" (no mention of waiting on the map). factory:standards-change rule 1. Confirm this interpretation in `design.md`'s Decisions, or show the sidebar as soon as a project is open.
- Nit: crates/agent-sessions/src/ui.rs:188 / src/app.rs:742 — requirement 11's "while the search field has focus, the map's letter and bracket keys do nothing" and the `[`/`]` session-stepping have no acceptance test (the 9 scenario tests only cover the Gherkin background scenarios; design.md's own Risks section flags step 4's key routing as "riskiest" but relies only on pre-existing, unrelated acceptance tests to guard it). factory:standards-testing rule 6.
