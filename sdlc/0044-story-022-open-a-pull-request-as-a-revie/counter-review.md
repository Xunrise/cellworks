# Counter-review

Standards applied: factory:standards-change, factory:standards-security, factory:standards-testing

- Important: src/app.rs:1038 — When Esc closes the open project while a review is mid-checkout or mid-mapping (picked a pull request but `Navigation::enter_review` has not run yet, so `navigation.esc()` returns `Moved::Closed` instead of `LeftReview`), the `Moved::Closed` arm sets `app.opened = None` but never clears `app.review`; the background checkout/mapping for the abandoned pull request keeps running, and `apply_pending`'s unconditional drain (line ~511) will later call `open_review_head`, silently reopening a project the engineer explicitly closed. This is the same failure mode the design's own counter-review fix (design.md "Fix (counter-review)") already fixed for "open a different project" but missed for "close the project via Esc"; it contradicts requirement 8 ("Esc leaves… also from inside a tower" ends the review as the one and only escape mechanism) and requirement 11 (a stale checkout must be ignored). standards-change: rule 1 (the change departs from its own stated intent without updating anything) / rule 3 (fail loudly, not silently resurrect a closed project). Fix: also clear `self.review` in the `Moved::Closed` arm (or have `app.opened = None` always go through the same path that drops `self.review`, as `CellworksApp::open` already does).
- Important: docs/arc42/09-decisions.md, docs/adr/0009-pull-requests-through-gh-and-git.md — design.md states "ADR needed: yes, ADR-0011 'Review mode opens the pull request head as the city'… ADR-0009 gains one cross-reference line" and its Docs impact section promises `09-decisions.md`: "the ADR-0011 line", but no `docs/adr/0011-*.md` file exists on this branch, `09-decisions.md` lists no ADR-0011 entry, and `0009-pull-requests-through-gh-and-git.md` carries no cross-reference to it (a sibling branch, `proto/review-city`, did create exactly this ADR and these two edits, but that commit never reached this branch). standards-change: rule 1 (the change must match what its own plan/design says it does) and rule 5 (docs stay true — the design's Docs impact claims are false for this diff). Fix: add ADR-0011 recording this decision, list it in `09-decisions.md`, and cross-reference it from ADR-0009, as design.md commits to.
- Nit: crates/sources/src/pull_requests/mod.rs (`advance`'s `ReviewState::CheckingOut` branch in src/review.rs) — the catch-all `Ok(_) => (ReviewState::CheckingOut { .. }, None)` arm silently accepts any `PullRequestEvent` variant other than `CheckedOut`/`OpenFailed` (e.g. a hypothetical `Listed`) without comment; a short note that `start_check_out` only ever sends those two would make the exhaustiveness intentional rather than accidental.
- Nit: crates/sources/src/pull_requests/forge.rs — `parse_listing` and `parse_issues` duplicate the same ASCII record/field-splitting shape (split on `\u{1e}`, filter empty, `splitn` on `\u{1d}`/`\u{1f}`); a small shared helper for "split records, drop the trailing empty one" would avoid maintaining the convention twice.
