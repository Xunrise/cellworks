- Important: tests/story_058_typescript_and_javascript_code_stands_as_towers.rs:176 — `every_file_of_the_family_is_read` uses the identical markup-free fixture (`export function load() {}`) for all four extensions, but design.md's own Proof section commits this test to fixtures where "the `.tsx` and `.js` fixtures return markup, pinning the TSX grammar" (design.md requirement 1 + Proof list). A plain function declaration parses identically whether `.js`/`.tsx` are read with the TypeScript grammar or the TSX grammar, so this test cannot catch a regression to the wrong grammar for the JS family — the one behaviour this scenario exists to pin. standards-testing: rule 6, "New behaviour arrives with its tests, including the error paths the spec or plan names." Give the `.tsx`/`.js`/`.jsx` fixtures JSX markup (e.g. `return &lt;div/&gt;;`) so the test fails if the TypeScript grammar is used for them.

Expose `rust::LARGEST` (`pub(crate)`, e.g. moved to `items.rs` alongside the other shared constants) and import it instead of duplicating the literal.
