# Counter-review

Standards applied: factory:standards-change, factory:standards-security, factory:standards-testing (plugin `factory`).

- Important: src/app.rs:961 — `typing` (used to gate every bare-letter shortcut: E, I, A, G, U, Z, P, and the Explorer's own j/k/h/l) checks `app.sessions.search_focused` and the launcher's search field but never the Explorer's filter `TextEdit` (`crates/navigation/src/ui.rs:97`, id `"explorer filter"`), unlike those two fields which the same comment block says exist precisely to stop "every u, m and z…" also firing a shortcut. Typing into the filter (e.g. "lib", "base", anything containing e/i/a/g/u/z/p/j/k/h/l) therefore also toggles the Explorer closed, toggles ignored files, toggles lanes, folds/unfolds/moves the cursor, etc., while the user is naming a filter — breaking requirement 6 ("not typing") and requirement 7 ("is not typed into it") of `design.md`. standards-testing: rule 2 — the one test that exercises the filter, `filtering_narrows_the_rows_by_name` (via `type_into_focused` in `tests/story_089_navigate_a_project_from_the_explorer.rs:72`), only pushes `egui::Event::Text`, never a matching `egui::Event::Key`, so it cannot fail even though this is broken for a real keystroke. Expose the filter field's focus (an id-based `explorer_filter_focused` helper, the same pattern as `cellworks_workspace::ui::search_focused`) and fold it into `typing`, then make the filter test simulate real key+text pairs.
- Important: crates/navigation/src/explorer.rs:237 — `beside` exempts only `area == whole` (the exact map extent) or a narrow window; it has no way to recognise a user-zoomed camera. `navigation.zoomed` (called unconditionally from `src/app.rs:1605`, including while the Explorer is open) sets `Navigation::camera`, and `framing()`'s early-return then reports that exact zoomed rect — not `map.extent` — as `framing.area`. `project()` (`src/app.rs:1705`) calls `beside` on that area whenever the Explorer is open, so any zoom that isn't coincidentally a perfect fit gets shifted left by the panel margin. This contradicts requirement 10 of `design.md` ("Framing is not shifted for … a user-zoomed camera"). standards-change: rule 1 (the change matches its plan) — no unit test covers a zoomed, non-`whole` area through `beside`, only `rows_list_folders_first_and_count_files`'s sibling test `beside_shifts_folder_and_node_framing_but_not_the_whole_project_nor_a_narrow_view` checks `whole` and narrow-window, not zoom. Pass whether the camera is user-set into `beside`'s exemption (or skip the shift entirely when `navigation.camera().is_some()`), and add a test for it.
- Important: src/app.rs:1181 — the `h`/`ArrowLeft` handling (fold the current row, or step to its parent when already folded) that implements requirement 6 of `design.md` has no test anywhere: no unit test on `Explorer::fold`/`step`, and no acceptance test presses `Key::H` or `Key::ArrowLeft` while the Explorer is open (confirmed: no occurrence of `Key::H` or `ArrowLeft` combined with Explorer tests in `tests/`). standards-testing: rule 6, "New behaviour arrives with its tests". Add a unit test on `Explorer` (fold toggling) and/or an acceptance test exercising `h`/`ArrowLeft` for both the fold and move-to-parent branches.
- Nit: src/opened.rs:485 and crates/navigation/src/explorer.rs:292 — `count_nodes` (new, hand-rolled recursion over districts/sub-districts/groups) duplicates the same "every node of a folder, however deep" walk this very change already writes as `count_files`, both reimplementing the pre-existing `pub(crate) fn nodes(district: &District)` in `crates/map/src/graph.rs:367` a third time, just not exposed publicly. standards-change: rule 2, "Reuse before adding". Expose one counting function on `ProjectMap`/`District` in the `map` crate and have both call sites use it.
